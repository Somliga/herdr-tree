## The next piece of work: compaction in one key

This is what the user asked for, and it is the reason this handoff exists.

**What they want:** pressing `s` on a range should not merely produce a
summary to fold in later — it should *replace that stretch of the
conversation with the summary*, so the line's context actually gets smaller.
Automatically, in one step.

**The important thing to understand before designing anything: the mechanism
already exists.** A fold-back that grafts is a rewind, and a rewind truncates.
`claude.Select` (`internal/claude/graft.go`) walks the ancestor chain back
from the graft point, so every turn *after* that point is simply absent from
the new transcript. Fold a summary of turns 5..12 in at turn 4 and the new
session contains turns 1–4 plus the summary. Turns 5–12 are gone from that
line's context. That is compaction, and it works today.

What is missing is only that the user has to do it in two steps and pick the
graft point by hand:

1. `s` at turn 12, move to turn 5, `s` again → summary stored
2. move to turn **4** — the turn before the range — and press `p` → picker →
   `⏎`

Step 2's graft point being "one before the range's start" is the fiddly part,
and getting it wrong by one turn silently keeps a turn you meant to drop.

**The shape of the work**, then, is composition rather than new machinery:
after a summarise completes, graft at the parent of the range's start and seed
it with the summary. `Model` already has the parent link (`m.parent`, used by
the fold-out path around `internal/tui/model.go:458`). `claude.GraftSeeded`
already takes the seed. `foldBackSeed` already picks the `⤶ compacted` prefix
when the operation rewinds within one session, and §6b already colours that
blue, meaning "this line contracted" — which will finally be literally true.

**Design questions to settle with the user before building it** (do not guess;
this touches their real conversations):

- Should `s` always compact, or should compaction be a second key so that
  "summarise for later, fold in elsewhere" stays available? The spec's §5
  deliberately separates producing a summary from placing it, and the user
  earlier asked for summarising to be *offered, never forced*.
- The range's start has a parent only if it is not the session's first turn.
  What happens when someone selects from turn 1?
- A compaction creates a new session and leaves the old one on disk, because
  nothing in this project deletes a session the user could still resume. Is
  the user expecting the old line to disappear from the tree? It will not, and
  should not — but they may expect it to.
- Compacting *while sitting in the session being compacted* means the live
  agent is now on the abandoned line. The new session has to be opened and the
  user moved to it. That is the `⏎`-resume path, already built, but the
  handover moment is worth designing rather than inheriting.

Start with `superpowers:brainstorming`. This is a behaviour change to how the
user's conversations are rewritten; it is not a bounded tweak.

## How the feature works today, for orientation

`prefix+t` opens the overlay. Footer keys, unranged:
`↑↓ move · ←→ fold · ⏎ continue · s summarise · p fold back · L label ·
a scope · f filter · esc close`.

- **`s`** fixes the *end* of a range at the cursor, then you move to its start
  and press `s` or `⏎` again. End-first is deliberate: "summarise what I just
  did" is how the thought arrives and the cursor is already there. `esc`
  cancels a range; escaping the *cost dialog* keeps it, so you can move the
  start.
- **`p`** folds a stored summary in at the cursor. Tip of a session that is
  open in a live Herdr pane → delivered as a message via
  `herdr.AgentPrompt`, nothing copied. Anywhere else → a seeded graft. The
  picker states which before you commit, and a failed send never silently
  falls back to grafting.
- **`⏎`** continues from a turn: resumes in place at a tip, branches
  otherwise.

## What is NOT verified, and matters

1. **`herdr agent prompt` delivering a multi-paragraph summary to a live
   agent.** The spec itself flags this (§10 Q3) and v2's headline path rests
   on it. `scripts/verify-timeline.sh` exercises the rest and says plainly
   that it does not cover this. Herdr's own documentation warns that
   successful submission does not prove the agent started a turn.

2. **The first bytes of a delivered entry.** This overturned an earlier
   ruling and is the sharpest open risk. `Classify` decides an entry is an
   injected summary from its `⤶` prefix at byte zero. When *we* write the
   entry that is guaranteed by construction. But the message path hands text
   to a terminal and **Claude Code writes the entry, not us** — a
   bracketed-paste artefact or a BOM ahead of the marker drops the entry to
   `KindHuman`, so a folded-in summary renders as something the user typed,
   losing its marker and its colour. That is precisely what spec §6 exists to
   prevent. Nothing tests it because it is the unverified path above.

`scripts/verify-timeline.sh` spends real API budget and must never run in CI.
**The user is actively watching their spend — get explicit approval before
running it, `scripts/verify-graft.sh`, `cmd/timelinecheck`, or the `claude`
binary in any form.**

## Standing constraints, all absolute

- Never modify a source transcript. Never delete a session the user could
  still resume. Grafted transcripts are written mode 0600.
- Never log message content. A summary *and a turn title* are both message
  content. Four separate leak routes were closed late in this branch — herdr's
  stderr, claude's stderr, a dash-leading message being quoted back, and row
  titles. Assume there is a fifth.
- **Do not touch the user's live Herdr session**, its panes, or
  `~/.config/herdr/`. They are working in it. Two agents on this project hit
  it despite being told not to — once installing the plugin and editing the
  config, once shelling out to the real binary during a mutation. The
  countermeasure is structural, not an instruction: when mutation-testing
  anything that can `exec`, put a stub binary first on `PATH`. See
  `stubHerdr` in `internal/herdr/herdr_test.go` and `stubClaude` in
  `internal/claude/summarise_test.go`.

## Lessons this branch paid for

Worth knowing, because each one cost real time here.

- **Tests catch wrong implementations reliably and wrong ideas never.** Every
  defect that mattered in v2 was found by rendering real data and looking at
  it, or by mutating code and watching a green suite stay green. None were
  found by reading.
- **Six tests on this branch could not fail when written.** The pattern is
  always a fixture that cannot occur in reality: a synthetic row title that
  never collides with the real prefix (hid a doubled `⤶` on screen), a
  graft-cycle fixture proving a guard that turned out unreachable, a zero
  value sitting exactly where two orderings agree. Check each fixture against
  what the real code path produces.
- **A mutation that deletes code and leaves a variable unused fails to
  compile and proves nothing.** Mutate to a live-but-wrong expression. This
  mistake was made six times here.
- **A verification step that asserts an outcome it did not check is the same
  defect as a test that cannot fail** — including a shell `echo` saying
  "green" after a command that was red.
- **An instruction in a prompt is not an access control.**

## Open items, none merge-blocking

Recorded in full at the end of the ledger, with rulings. Briefly:

- `GraftSeeded`'s `.graft-*` temp file is orphaned in the user's real project
  directory if the process dies between create and rename. Unavoidable if the
  write is to stay atomic; invisible to `Discover`'s `*.jsonl` glob.
- `RangeSpan` and `rangeIndices` are the same lookup with different
  tie-breaks. Dormant — `Rows()`'s visited guard makes a duplicate node
  impossible — and collapsing one onto the other is cheaper than the
  deferral.
- `ErrAgentBlocked` has no `errors.Is` consumer: `SendFunc` returns a plain
  error, so it surfaces as text. It works; it is not a sentinel.
- `summariseConfirmText` counts *visible* rows, so a range covering 40
  entries can report "8 row(s)" when sections are folded.
- Interrupting a call with `ctrl+c` cannot stop the spend: quitting exits the
  process and the watchdog dies with it. The first press now says so and the
  second still leaves. The correct fix is threading a context through
  `adapter.Adapter.Summarise`, which is an interface change touching three
  implementations.
